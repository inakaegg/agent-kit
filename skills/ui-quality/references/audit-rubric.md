# Visual Audit Rubric

実画面またはレンダリング画像を直接確認した場合だけ採点する。ソースコードだけでは採点しない。

各項目を `0–2` で評価する。

- `0`: 破綻、重大な欠落、または目的を満たさない。
- `1`: 使用可能だが明確な不整合・弱点がある。
- `2`: 一貫し、目的とプラットフォームに適合する。

## 評価項目

1. **目的・階層・主要アクション**  
   画面の主役、読み順、次の操作が明確か。

2. **構成・整列・グリッド**  
   端、baseline、列、まとまり、視覚的な関係が整っているか。

3. **余白・密度・タイポグラフィ**  
   間延びや過密、極端な小文字、二重paddingがなく、読みやすいか。

4. **コンポーネントとトークンの一貫性**  
   同格のボタン、入力、アイコン、色、角丸、状態表現が統一されているか。

5. **サイズ・長文・状態への耐性**  
   対応幅、window resize、長い文言、empty、loading、error等で破綻しないか。

6. **操作性・アクセシビリティ・プラットフォーム適合**  
   focus、keyboard／touch、contrast、disabled、OS／Webの慣習が適切か。

7. **視覚的完成度とプロダクトらしさ**  
   不要な装飾やテンプレート感が少なく、参照画像と既存画面に整合するか。

## 合格条件

- 合計 `12/14` 以上
- `0` の項目がない
- 次のblocking defectがない

Blocking defect:

- clipping、overlap、操作不能
- 意図しない横スクロール
- 主要アクションが識別できない
- 同一グループの同格コントロールに明白なサイズ不一致がある
- 必須状態または主要viewportでレイアウトが破綻する
- focus不能、読めないcontrastなど主要操作を妨げるアクセシビリティ問題がある

## 監査手順

1. まず実画面をソースの意図で正当化せず観察する。
2. 問題ごとに画面、状態、サイズ、重要度、根拠を記録する。
3. 実装担当が修正する。
4. 同じ条件で再撮影・再操作する。
5. blocking defectが消え、合格条件を満たしたことを再確認する。

修正前スコアは変更前の実画面を確認した場合だけ記録する。スコアのために問題を軽く評価しない。

実画面を直接確認できない場合は採点せず、次だけを記録する。

`VISUAL_QA_UNVERIFIED`
