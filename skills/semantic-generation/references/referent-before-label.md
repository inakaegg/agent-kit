# 語より先に指示対象を固定する

対象文書では対応表を独立提出してから本文を書く。対応表なしで本文を書き始めた場合は、
本文を破棄し、対応表から作り直す。

骨組みや見出しに、未整理の作業を抽象名詞で包んだ作業ラベルを使わない。
新語や造語は初出定義を書ける場合だけ導入し、書けなければ指す対象を具体記述へ分解する。

## この規律が防ぐこと

対象が曖昧なまま語を先に置くと、指示対象とのずれが訂正されないまま、設計文、状態名、
条件名、メソッド名、型名へ波及する。この規律は誤用語の一覧と照合するのではなく、
語を置く前の生成順序を固定する。

## 適用範囲

次のいずれかに該当する作業だけに適用する。判断できない場合は適用する。

1. 設計資料、要求からの設計、調査報告、原因切り分け案、対策案を書く。
2. 公開仕様、状態名、条件名、事象名、値や記録の型名、メソッド名、boolean名を決める。
3. ユーザーが与えた推論順序を短い作業ラベルへ要約する。

ユーザー原文の引用、単純な機械編集、既存名の再利用、定型出力、雑談、
確立した用語だけで書ける短文には適用しない。

## 常時守ること

- 対応表を本文とは別のファイルまたは別のturnで先に提出する。
- 完成文書の先頭に表を置くだけで、先に作ったことの代用にしない。
- 骨組み、見出し、結論に、目的・対象・判断を省いた抽象的な作業ラベルを使わない。
- 新語を導入するときは、初出に「Xとは〜を指す」と定義する。
- 定義できない語を導入せず、指す対象をそのまま文で書く。

## 通常の流れ

1. 対象文書に該当するか判定する。
2. `semantic-generation` Skillを使い、対応表を独立成果物として先に保存する。
3. 対応表に載った語を中心語彙にして本文を書く。
4. 日本語文、設計要素、コード識別子で同じ対応を保つ。

## 手順を外した場合

- 対応表を提出せず本文を書き始めた場合は、本文を破棄する。
- 後付けで表を追記せず、対応表を独立提出してから本文を再生成する。
- Skillを利用できない環境では、最低6列
  (`出典 / 目的 / 具体対象 / 役割 / 前後関係 / 候補語`) の対応表を先に保存する。
