# 図作成の落とし穴と根拠

実例から得た知見。一般論ではなく、実際に起きた失敗とその原因を書く。

## diagrams の既定ノードは「アイコンと文字が同じ固定サイズの箱」

- 既定は `width 1.4` / `height 1.9` インチ、`fixedsize=true`、`imagescale=true`。アイコンは箱を埋めるように拡大され、文字は箱の下端に置かれる。
- 文字だけ大きくする（`fontsize` 18 など）と箱からはみ出し、隣のノードのラベルと重なる。
- 箱を小さくする（`width 0.9`）とアイコンは縮むが、文字の置き場も縮み、やはり重なる。
- 解決: HTML ラベル（`<TABLE>` に `<IMG>` と `<FONT>`）。アイコンの px と文字の pt を独立に決め、ノード幅は文字幅から自動で決まる。`assets/diagram_template.py` の `svc()`。

## 矢印ラベルの位置

- 横並び（`direction="LR"`）で長い矢印が多いと、Graphviz はラベルを矢印から離れた場所に置く。別の矢印のラベルに見えて誤読を招く。
- 構成図は `TB`（上から下）のほうがラベルが矢印の横に付きやすい。経路図のような一本道は `LR` でよい。
- 右端に回り込む長い矢印のラベルは短くする（図の横幅を数百 px 広げる）。

## 群の順序

- 「後回し」「将来」の群は edge で結ぶと矢印が散らかる。結ばずに invisible edge（`Edge(style="invis")`）で最下段へ固定する。

## GitHub 上の表示

- README では JavaScript も CSS も剥がされるため、ライトボックス（遷移なしの拡大）は作れない。画像クリックは原寸へのページ遷移になる。
- 本文幅は約 830px。それより広い図は縮小表示される。13 ノード程度の構成図は 1,700px 幅ほどになり、約半分に縮む。
- 対策は SVG。ブラウザのズーム（⌘+ / Ctrl+）で文字がぼやけない。PNG だと拡大でぼやける。
- Mermaid だけは GitHub がズーム・パン操作を付ける。ただし AWS 等のアイコンは出ない（iconify のアイコンパックを登録できない）。
- ノード数を減らして縮小を避ける案は、読者が望まないことが多い。一瞥で全体が見えることに価値がある。

## SVG の注意

- Graphviz の SVG はアイコンを `xlink:href="/abs/path.png"` で参照する。そのままでは GitHub で表示できないので base64 で埋め込む（`finalize_svg()`）。
- 文字は閲覧側のフォントで描かれる。生成時のフォント（Hiragino Sans）しか指定しないと Windows で代替フォントになり文字幅が変わる。`font-family` を複数候補に置き換える。
- 確認は PNG に変換して目視する（macOS: `qlmanage -t -s 1800 -o <dir> <svg>`。正方形に切り出されるので右端は欠ける）。

## 環境

- diagrams は Graphviz の `dot` が必要。macOS は `brew install graphviz`（約 8MB、system 変更なので一言断る）。
- `uv run --with diagrams python <script>` で仮想環境を作らずに実行できる。diagrams は公式アイコンを同梱（約 33MB）。
- アイコンのパスは `Path(diagrams.__file__).parent.parent / cls._icon_dir / cls._icon`。`cls("")` でノードを作って調べると、そのノードが図に残るので使わない。

## 文字サイズの目安（ICON_PX 72 のとき）

| 要素 | pt |
|---|---|
| ノード名 | 16 |
| 補足行 | 13 |
| 矢印ラベル | 13 |
| クラスタ名 | 15 |
| 図のタイトル | 15 |

ラベルは 1 行 12 文字程度。それ以上は `\n` で折る。
