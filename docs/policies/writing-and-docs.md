# 文書の執筆担当と構成の規則

共通 `AGENTS.md` §3・§5 の骨子を前提とする。本ファイルは文書を新規作成・実質更新・再編するときだけ読む。手順は `$docs-maintenance`、日本語の書き方は `$natural-japanese`、用語の選び方は本kitの `docs/terminology-ja.md` を併用する。

## 執筆担当の判定

- 文書の執筆担当は、pathや拡張子ではなく**主な読者**で判定する。人間を主な読者・承認者・成果物の受け手とする文書（README、利用者向けdocs、製品仕様、設計文書、設計判断の記録、release note、人間がreviewする提案・調査報告など）の新規作成と本文の実質的な更新は、Claude Code自身が執筆・編集しなければならない。人間とAIの双方が正式に使う文書、および主な読者を判定できない文書も、人間向けとして扱う。
- 人間向け文書のうち、設計・仕組みをユーザーへ平易に説明する解説文書は、利用可能な範囲で最上位の深い思考用モデル（`WRITING_MODEL_DEEP` が示す担当。agent-settings、`AGENTS.md` §1）のセッションが、対象の仕組みを自分で理解したうえで執筆する。他のセッションは素材（実測値・実例）の提供までとする。
- AI・agentだけが使う文書（task契約、active plan、引き継ぎ、prompt、機械処理用の文書）は、Codex等の別agentが作成・更新してよい。ただし規則ファイル（共通 `AGENTS.md`、projectの `AGENTS.md`・`CLAUDE.md`）の本文編集は、原則として `WRITING_MODEL_DEEP` が示す担当のセッションだけが行う。他のセッションは変更案の提示までとする。
- 人間向け文書について、Claude以外のagentは事実確認、要件・制約の整理、Claudeへ渡す入力の作成、生成された差分のreview、command・link・testの検証を担当してよく、最終本文を代筆してはならない。Claude Codeが利用不能、権限不足、またはそのターンで実行を許可されていない場合は、別agentが代筆せず停止して理由を報告する。

## 文書構成の既定

プロジェクトが別の構成を定めていない場合、次を既定とする。

- `README.md` — 主文書。初見の人に伝えたいこと（何を作るか、方向性、構成図、技術構成、動かし方）を書き、詳細は `docs/` へリンクする。目次だけの README にしない。
- `docs/` — 詳細の正本。データ項目の定義、仕組みの説明、費用の設計など。
- `docs/decisions/` — 設計判断の記録。`001-DynamoDBを採用する.md` のように番号と「何を決めたか」の平叙文で名付け、決めた内容・理由・検討した代替案・トレードオフを短く残す（ADRと呼ばれる形式）。
- `docs/CLI.md` — 貼ればそのまま動くコマンドの表。
- `docs/ROADMAP.md` — 実装の順序と進み具合。
- プロジェクトの `AGENTS.md`・`CLAUDE.md` には、そのプロジェクト固有の規則の差分だけを書く。技術選定・仕様・データの扱いは文書側（README・docs/）に属し、規則ファイルへ書かない。

## 状態記述は1箇所

実装状況・進み具合・「現状は〜」の類を書く場所は `docs/ROADMAP.md`（またはプロジェクトが定めた1箇所）に限る。各文書の冒頭に更新日を置かない。状態の注記を複数の文書へ撒くと、書いた瞬間から腐り始め、更新の手間だけが増える。文書本文は設計と仕様を書き、状態はROADMAPと git 履歴に任せる。

## 用語の選び方

- 日本の開発現場で一般的でない英語圏のソフトウェア工学用語・略語を、説明なしに導入しない。
- 日本語で広く定着したカタカナ語（API、フォールバック、キャッシュ、リファクタリング等）はそのまま使う。
- 英語の直訳で日本語としてかえって分かりにくくなる語（例：regressionの「回帰」単独使用）は、日本のエンジニアが一般的に使う表現を優先する。
- 対応表は本kitの `docs/terminology-ja.md`。表にない語も上の3原則で自分で判断し、書いた本人が推敲する。禁止語辞書を増やし続けることを対策にしない。

## 文書更新のレビュー

人間向け文書の新規作成と本文の実質的な更新は、`REVIEW_MODEL_READABILITY` が示す担当の、履歴を共有しない別セッションによる読みやすさレビューを通してからcommitする。誤字修正・リンク修正等の軽微変更は対象外。レビューの回数・指摘の扱いは本kitの `docs/policies/review.md` に従う。
