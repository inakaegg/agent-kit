# 複数エージェントの並行作業と直接連携

> 対象: 2つ以上のコーディングエージェント(例: Claude fable系 + Claude Opus、Claude + Codex)が同一タスクで並行し、互いのチャット履歴を直接監視して連携する場合。単独作業では読まなくてよい。

**現行の入口は `$pair` であり、`$agent-collab` は廃止された。** 現行の詳しい手順の正本は `common-agents/skills/pair/SKILL.md` とその `assets/`・`references/` にあり、本文書はそれを置き換えない。現行のpairのtransportは相手タイプで切り替わる(Claude相手: SendMessage受信駆動、Codex相手: ファイルinbox/outbox+rollout監査)。常駐監視scriptは使わない。

本文書末尾の「旧方式」節にある常駐監視・JSONL pollingの手順は、`$agent-collab` 時代の歴史資料であり、現行の規範ではない。以下の「役割分担」から「切替とhandoff」までは、現行の `$pair` 体制でも有効な運用規則である。

## 役割分担

- 既定の分担は、深い思考用モデル(現在はfable系)のセッションが仕様策定・規則・人間向け文書・レビュー統括を担い、実装用エージェント(Codex、Claude Opus等)がコード・テスト・機械向け文書を担う。
- 各gateのreviewは、当該成果物を実装・作成していない側のエージェントが起動・統括する。reviewer自体のfresh context要件と件数上限は共通AGENTS §7に従う。
- 同一worktreeを複数エージェントが同時編集しない。「実装・commit担当1つ」と「read-onlyのreviewer・検証担当」へ分離する。
- 数値の合格条件(gate値)は未検証の見積もりで固定しない。実データの測定から導出し、実装側が届かない場合は原因を測ってから仕様側の訂正かコード側の修正かをtriageする。

## ユーザーへの質問と停止

- ユーザーは各エージェントのチャットを見ている。判断を仰ぐ内容は専用ファイルを介さず、自分のチャットへ質問として書く。
- ユーザーの意思決定が必要な選択に達したら、自分で仮決定して先へ進まず、質問を書いて停止する(共通AGENTS §10)。実装エージェント側にも同じ規則を適用する。

## 起動済みreviewer・サブエージェントの待機

- 無出力は失敗ではない。待機そのものはtokenを消費しない。待機中は新しいpromptを投入せず、差分監視だけ行う。
- 明示的なerror、process終了、設定不備が確認できない限り、開始から最低30分は中断しない。中断は途中までの推論tokenを捨て、再実行で二重に消費する。
- 中断・未完了のreviewはgateのroundに数えない。再実行は明示的失敗を確認した場合だけ行い、可能なら先に相手エージェントへ状態を確認する。
- 同じgateのreviewを両側から二重起動しない。どちらが起動するかを先にチャットで合意する。

## 切替とhandoff

- どちらかのエージェントが利用上限・障害で止まる見込みになったら、未commit差分、実測値、検証結果、gate状態を現在のタスクの `_ai/tasks/<タスクslug>/` 配下のhandoffへ固定してから停止する。
- 後任エージェントは、handoffとタスク契約を読み、実測値を1つ再現確認してから作業を引き継ぐ。

## 旧方式(廃止): `$agent-collab` の常駐監視

> 以下は廃止済みの `$agent-collab` 方式の記録であり、現行の規範ではない。現行の入口は `$pair`、現行手順の正本は `common-agents/skills/pair/SKILL.md` とその `assets/` である。

開始手順は `$agent-collab` Skillに自動化されている。各エージェントのチャットで任意のタイミングで `/agent-collab` と打てば、役割の自動判定(モデル種別から)、相手セッションの自動発見と増分監視の常駐起動、開始宣言まで行う。監視スクリプトの正本はそのSkillの `assets/watch-partner.py` であり、毎回書き直さない。

### 相互のチャット履歴監視

セッションログの場所(例):

- Claude Code: `~/.claude/projects/<プロジェクトslug>/<セッションID>.jsonl`
- Codex: `~/.codex/sessions/<YYYY>/<MM>/<DD>/rollout-*.jsonl`

読み方の規則:

1. 全文をモデルへ流し込まない。ローカルでJSONLを走査する処理自体はmodel tokenを消費せず、モデルのcontextへ返した文字だけが消費する。抽出前の全件dumpを避ける。
2. セッションごとに前回読んだbyte offsetをstateへ保存し、次回は追記分だけを読む。offsetの保存は抽出の成功後に行う(先に保存すると失敗時に欠測する)。
3. 抽出対象は、user/assistantの本文、tool名と短い要約、`VERDICT`・error・停止条件を含むtool resultだけとし、それぞれへ文字数上限を置く。poll間隔は20〜60秒程度。
4. 監視対象セッションを固定しない。毎poll(または再開時)に最新のセッションファイルを再選定し、相手の再起動・新セッションへ自動追随する(日付が変わって別directoryへ作られる場合を含む)。
5. 監視処理を想定外の入力形で落とさない。例外は握って1行報告し、継続する。落ちて再開した場合は欠測区間を一度だけ再走査する。毎回先頭から読み直さない。
6. 相手への技術連絡は、自分のチャット出力へ直接書く(相手が監視して読む)。連絡用の中間ファイルをlog代わりに使わない。
