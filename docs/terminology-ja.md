# 用語集: Coding Agentが使いがちな語 → 日本のIT現場で自然な表現

<!-- textlint-disable prh -->
<!-- 本ファイルは「やめる語」自体を収録する対応表のため、言い換え辞書(prh)の検査を無効にする -->

## 原則

日本の開発現場で一般的でない英語圏のソフトウェア工学用語・略語を、説明なしに導入しない。日本語で広く定着したカタカナ語（API、フォールバック、キャッシュ、リファクタリング等）はそのまま使う。英語の直訳で日本語としてかえって分かりにくくなる語（例：regression→回帰）は、日本のエンジニアが一般的に使う表現を優先する。

## 言い換える語

表の引き方：英字の語はアルファベット順、日本語の語（直訳調・AI調の日本語）はその後に五十音順で並べる。

### 日本語の語（五十音順）——直訳調・標準規格調でかえって伝わらない語

| やめる語 | 使う言い方 | 備考（出典・注意） |
|---|---|---|
| 回帰（単独使用） | デグレ、リグレッション、既存機能が壊れること | 「回帰テスト」という複合語は定着しているが、「回帰が発生した」「回帰を防ぐ」はAI調。日本の「デグレ」は英語のregressionにほぼ相当（chatgpt01） |
| 縮退 | フォールバック、機能を落として動き続けること | 「縮退運転」はメインフレーム・インフラ系の一部でだけ通じる。Web系では「フォールバック」が自然 |
| 検証と妥当性確認 | V&V、テストでの品質確認 | JISA VSE手引きの対応表より（実確認）。規格用語をそのまま使わない |
| 構築（規格用語として） | 実装、コーディング、製造 | JISA VSE手引きの対応表より（実確認）。「環境構築」の意味の構築は普通に使う |
| コスト防御 | 費用が暴走しない仕組み、費用の上限管理 | cost guard系の直訳。日本語として存在しない |
| 作業記述（SOW） | 業務記述、作業範囲の記述書 | JISA VSE手引きの対応表より（実確認）。SOWはSIer契約文脈では通じる |
| 敷き・敷く（表示の強調に対して） | ハイライト、強調表示 | highlight の独自訳で意味が通じない（作者指示 2026-08-31）。文書・UI文言・コメント・報告のすべてで使わない |
| 実行可能な（actionableの直訳） | 対応可能な、具体的に動ける | 「実行可能な指摘」は executable と紛らわしい。「対応が必要な指摘」と書く |
| 縮小（scale downの直訳で「機能縮小」以外） | 台数を減らす、規模を絞る | 文脈を具体化する |
| 妥当性確認 | 受け入れテスト、要件を満たすかの確認 | validation の規格訳。単独では通じにくい |
| 鳴らす・鳴る（音声・発話に対して） | 再生する、読み上げる、再生中の〜 | 言葉は話すもの、音声は再生するもの。鳴らすのは楽器だけ（作者指示 2026-08-29）。文書・UI文言・コメント・報告のすべてで使わない |
| 道具（CLI・外部コマンドに対して） | CLI名、ツール名、外部コマンド | tool の直訳で対象が曖昧（作者指示 2026-08-31）。claude・codex・yt-dlp 等は「CLI」「ツール」「外部コマンド」と呼ぶ |
| 統合（工程名として） | 統合試験、結合テスト | JISA VSE手引きの対応表より（実確認）。日本の現場は「結合テスト」が優勢 |
| 発見事項 | 指摘、指摘事項 | finding の直訳調。監査文書以外では「指摘」 |
| 要求事項 | 要件、要求、仕様 | JISA VSE手引きの対応表より（実確認） |
| 横断表 | 対応表、一覧表 | AI造語調。普通の日本語で書く |
| 論点（issueの機械的訳） | 問題、課題 | 会議の「論点」は正しい日本語。バグの意味では使わない |

## そのまま使ってよい定着語

カタカナ語：

- API、フォールバック、キャッシュ、リファクタリング、ロールバック、デプロイ、リリース、ビルド、マージ、コミット、ブランチ、レビュー
- テストケース、バグ、デバッグ、ログ、モック、スタブ、フレームワーク、ライブラリ、ミドルウェア、パフォーマンス、スループット
- レイテンシ（低遅延文脈）、タイムアウト、リトライ、バッチ、ジョブ、キュー、トリガー、スキーマ、マイグレーション（DB文脈）
- エスカレーション、トレードオフ、デグレ、リグレッションテスト、ステージング、スプリント、バックアップ、アーカイブ、インシデント、リスク、レビュアー、ドキュメント

英略語・英字：

- CI/CD、PR（プルリクエスト）、OSS、SLA、SLO、DB、UI、UX、SDK、CLI、IaC、JSON、YAML、REST、SQL、OS、VM、DNS、CDN
- LGTM（チャット・PRコメント内に限る）、E2E（テスト文脈）、QA、SRE、TDD、MVP（初出で「最小限の製品」と添えると親切）

漢語で定着しているもの：冪等、正常系・異常系、結合テスト、単体テスト、受け入れテスト、非機能要件、可用性、保守性、疎結合、排他制御、整合性。

## 機械照合用の固定記号

次の記号はツール・エージェントが機械的に照合するため、翻訳・言い換えをしない。

- `VERDICT: LGTM`
- `VERDICT: CHANGES REQUESTED`

前後の地の文は日本語で書いてよい（例：「レビュー結果は `VERDICT: LGTM` だった＝承認された」）。
